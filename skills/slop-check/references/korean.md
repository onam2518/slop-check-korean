# 한국어 슬롭 패턴

영어 스킬 열 개의 원칙은 한국어에도 그대로 적용된다. 사실·목소리 보존, 군더더기 제거, 능동태, 구체성, 리듬. 여기서는 한국어에서만 드러나는 표시와, 영어 규칙을 한국어에 옮길 때 달라지는 부분만 다룬다. 토큰 하나가 아니라 뭉치로 판단한다.

## 목표: 자연스럽고 전체적인 교정

한국어 검수의 목표는 슬롭 마커 몇 개를 지우는 게 아니라, 프로젝트가 만들어 낸 **산출물 전체가 사람이 자연스럽게 쓴 한국어로 읽히게** 하는 것이다. 슬롭 제거·어문 규범 교정·번역투 정리·용어 표준화·구성 손질을 **한 번의 통합 교정**으로 본다. 문법만 고치고 흐름이 어색하거나, 슬롭만 지우고 조사·호응이 틀린 채 두면 목표 미달이다.

생성 산출물처럼 지킬 저자 목소리가 없으면, 슬롭만 빼고 밋밋하게 두지 말고 **표준 문체 페르소나로 만든다**(→ `persona.md`, 제품 기본값). 진짜 저자 목소리가 있으면 보존이 우선. 사용자가 register·톤을 지정하면 그게 우선.

통합 교정 순서(위가 우선):

1. **보존 확정** — 숫자·이름·날짜·출처·인용·글쓴이 목소리를 고정한다. 없는 사실을 만들지 않는다.
2. **어문 규범** — 맞춤법·띄어쓰기·문장 부호(표기), 높임·조사·호응·피동/사동·시제(표현). 표기는 `bin/spellcheck.js`(부산대 검사기)로 확인하고, 나머지는 규범에 어긋난 것만 오류로. → `korean-correction.md`
3. **슬롭·번역투** — 서두 군더더기, 이분 대비, AI 상투 어휘, 무생물 주어, 피동 남용, `~되어집니다`·`단순한 X가 아니라 Y` 같은 번역투. → 이 문서
4. **용어 표준화** — 어색하거나 옮긴 티 나는 용어는 표준 용어로. → `korean-terminology.md`
5. **구성·흐름** — 중심-뒷받침 연결, 이탈 문장, 문단 흐름, 문장 길이 리듬. → `korean-correction.md`(내용·조직)
6. **자연스러움 최종 점검** — 소리 내어 읽었을 때 사람이 쓴 한국어로 들리는가. 규범에 맞아도 어색하면 다듬는다. 단, 과잉 교정으로 목소리를 밋밋하게 만들지 않는다(`preservation.md`).

`audit`은 각 층위의 문제를 근거와 함께 보고하고, `edit`/`rewrite`는 위 순서로 한 번에 자연스럽게 고친 전체 글과 변경 요약을 낸다.

## 원칙 (영어와 공통, 우선순위 그대로)

1. 숫자·이름·날짜·출처·인용은 그대로 둔다. 없는 사실을 지어내지 않는다.
2. 서두 군더더기를 자른다.
3. 이분 대비 상투구를 없앤다.
4. AI 상투 어휘를 평범한 말로 바꾼다.
5. 주어를 숨기지 않는다(무생물 주어·불필요한 피동).
6. 뭉뚱그리지 말고 구체적으로.
7. 문장 길이를 섞는다.
8. 형식 슬롭(이모지 라벨 불릿, 제목 과잉 굵게)을 없앤다.
9. 마무리를 "결론적으로"로 장식하지 않는다.
10. 뭉치로 판단하고, 이미 사람다운 글은 손대지 않는다.

## 글쓰기 기본 원칙 (positive)

슬롭을 지우는 것만으로는 부족하다. 처음부터 이 원칙으로 쓰면 슬롭이 덜 생긴다. (naradesign 「글쓰기 기본」 기반, 오웰 규칙과 결이 같다.)

1. **짧게 쓴다.** 설명·설득에서 **한 문장 12어절 이내**를 지향점으로 삼는다. 짧은 단어를 쓸 수 있으면 긴 단어를 쓰지 않고, 빼도 되는 단어는 뺀다. 능동태를 쓸 수 있으면 수동태를 쓰지 않는다. **단, 12어절은 슬롭 신호가 아니라 다듬기 목표다.** 실제 사람이 쓴 한국어 문장은 중앙값 15어절, 64%가 12어절을 넘는다(측정 근거: `references/korean-baseline.md`). 그러니 길다는 이유만으로 문장을 슬롭으로 잡지 않는다. 한국어에서 진짜 신호는 절대 길이가 아니라 **길이의 균일함**이다. 문장들이 다 비슷한 길이로 이어지면(낮은 burstiness) 기계 리듬이고, 짧고 긴 문장이 섞이면 사람 리듬이다. 한 문장이 뜻을 한 번에 못 읽을 만큼 엉키면 그때 쪼갠다.
2. **고쳐 쓴다.** 초고는 완벽할 수 없다. 생각을 먼저 쏟고, 여러 번 고치며 정리한 뒤, 맨 마지막에 맞춤법·띄어쓰기를 점검한다. 검수는 초안 작성과 분리된 단계다.
3. **담백하게 쓴다.** "매우, 무척, 정말" 같은 과장 부사와, 다른 글에서 익숙한 비유·직유·상징을 피한다. 개인의 고유한 표현이 없으면 차라리 담백하게. (앞의 상투어·부사 규칙과 같은 목표.)
4. **P-R-E-P 구조.** 설득·설명 글은 요점(Point) → 이유(Reason) → 사례(Example) → 요점(Point) 순서로. 핵심만 본문에, 세부는 뒤로.

이 원칙은 블로그·에세이·설명문에서 목소리를 살리는 쪽으로 쓰고, 법률·공지·기술 문서에서는 격식과 정확성을 우선한다.

## 서두 군더더기·신호어

말하기 전에 말하겠다고 알리는 표현. 잘라내고 바로 본론.

- "~에 대해 알아보겠습니다", "함께 살펴보겠습니다", "지금부터 ~를 소개합니다"
- "먼저, ~부터 짚어보겠습니다", "이번 글에서는", "본격적으로 들어가기에 앞서"
- "무엇보다도", "다시 말해", "결론부터 말하자면"(그리고 결론을 안 주는 경우)

## AI 상투 어휘

한 번은 괜찮지만 뭉치면 표시가 된다.

| 상투어 | 대체 |
|--------|------|
| 혁신적인 / 혁신적 | 무엇이 새로운지 구체적으로 |
| 원활한 / 매끄러운 | 어떤 마찰이 없는지 |
| 강력한 | 수치나 기능으로 |
| 획기적인 | 새로운, 처음 |
| 최첨단 / 최고의 | 근거를 대거나 삭제 |
| 다양한 (뭉뚱그릴 때) | 실제 항목을 나열 |
| ~을 극대화 / 최적화 (구체 없이) | 무엇이 얼마나 |
| 손쉽게 / 간편하게 (근거 없이) | 몇 단계인지 |
| 핵심적인 역할을 합니다 | 무엇을 하는지 |
| ~의 새로운 지평을 열다 | 삭제 |
| ~라는 점에서 주목할 만합니다 | 사실만 제시 |

## 유의미성 과장·홍보투

- "빠르게 변화하는 디지털 시대에", "오늘날", "AI 시대에" 같은 시대 선언 서두 → 삭제
- "~은 단순한 X가 아니라 Y입니다" (영어 not just X but Y의 번역) → Y를 바로 말한다
- "~라고 해도 과언이 아닙니다" → 삭제하거나 근거 제시
- 근거 없는 "전문가들은 ~라고 말합니다", "여러 연구에 따르면" → 출처를 대거나 삭제

## 번역투 (한국어 고유)

영어 문장 구조가 그대로 남은 흔적. 사람이 쓴 한국어에서는 드물다.

- **불필요한 피동:** "~되어집니다", "~라고 생각되어집니다", "개선될 수 있습니다"(행위자 은폐) → 능동으로, 주체를 밝힌다. "시스템이 캐시를 지웁니다"가 "캐시가 자동으로 지워집니다"보다 낫다.
- **무생물 주어 + 사람 동사:** "이 데이터는 ~을 말해줍니다", "결정이 내려집니다" → 사람이 한 일로.
- **군더더기 연결:** "~에 있어서", "~에 대하여", "~와 관련하여", "~을 통하여"의 남발 → 조사로 줄인다.
- **가짜 복수·추상명사:** "다양한 요소들", "여러 측면들에서" → 구체적인 항목으로.
- **`~적` 생략 압축:** "구체 정보", "구체 수치", "직접 원인"처럼 `~적`을 빼서 명사를 억지로 붙이면 어색하다. "구체적인 정보", "구체적인 수치", "직접적인 원인"으로. (반대로 `~적`·`~성`·`~화`의 *남발*도 슬롭이니, 빼도 자연스러우면 뺀다. 판단 기준은 소리 내어 읽어 자연스러운 쪽.)
- **"~적", "~성", "~화"의 남발:** "효율성의 극대화를 통한 생산성의 향상" → "더 효율적으로 만들어 생산성을 높인다".
- **"것이다" 남발:** "중요한 것이다", "필요한 것이다" → "중요하다", "필요하다".

## register 적합성 (오류는 아니지만 어울림)

둘 다 문법적으로 맞아도 register에 따라 더 자연스러운 쪽이 있다. 규범 위반이 아니므로 "오류"가 아니라 register 조정으로 다룬다. 지시가 있으면 모델이 맞출 수 있는 영역이니, 대상 글의 register를 먼저 정하고 통일한다.

- **목적 연결어미:** 격식체·문어(공지·마케팅·문서·논문·신문)에서는 "~기 위해 / ~기 위하여 / ~고자"가 기본. "~려고"는 구어·비격식 쪽이라 격식체 문장에 섞이면 뜬다. 예: (격식) "생산성을 높이기 위해" > "생산성을 높이려고". (신문 실측: 격식형:구어형 ≈ 11.6:1 — `korean-baseline.md`.)
- **문장 종결 통일:** 한 글은 한 종결체로. 문어 평서(보고서·논문·신문·기사)는 **~다** 통일이 기본이고, 합쇼체(공지·안내·발표·마케팅)는 **~습니다** 통일, 대화·비격식은 ~요. 셋을 한 글에 섞지 않는다. (실측: 문어 코퍼스는 ~다가 압도적 — `korean-baseline.md`.)
- **판단 기준:** 규범 검사기(`spellcheck`)는 이런 걸 못 잡는다(오류가 아니므로). register 적합성은 대상 장르를 정한 뒤 소리 내어 읽어 판단한다. 측정으로 뒷받침하려면 register 라벨 코퍼스가 필요하다(→ `korean-baseline.md`가 12어절을 실측했듯, 연결어미·종결의 register별 분포도 같은 방식으로 보정 가능).

## 마무리 슬롭

- "결론적으로", "요약하자면", "정리하자면" 다음에 앞 내용을 반복 → 마지막 구체적 사실로 끝낸다.
- "앞으로가 더욱 기대됩니다", "무궁무진한 가능성", "밝은 미래" → 실제 계획·사실·질문으로.
- 챗봇 잔재: "도움이 되셨기를 바랍니다", "궁금한 점이 있으시면 언제든 문의해 주세요", "~에 대해 더 알고 싶으신가요?" → 삭제.

## 형식·리듬

- 이모지 라벨 불릿(`- 🚀 **출시:** ...`), 제목 과잉 굵게, 모든 항목을 세 개로 맞추는 습관 → 영어 규칙과 동일하게 처리.
- 문장을 전부 "~습니다"로 같은 길이로 끝내면 기계 리듬이 된다. 격식체 자체는 문제가 아니지만, 길이와 종결을 섞는다. (짧은 문장 옆에 긴 문장.)
- **따옴표는 굽은따옴표(“ ”, ‘ ’)가 한국어 표준** — 신문 실측 곧은따옴표 0. 영어/코드용 곧은따옴표 규칙을 한국어 산문에 적용하지 않는다. 가운뎃점(·)·물결표(수치 범위)도 정상. em dash(—)·이모지 라벨 불릿은 정리, 산문 속 장식용 유니코드 화살표(→)도 정리(수치·경기 결과 등 기능적 사용은 예외).

## 그대로 두는 것 (과잉 교정 경계)

- 공식 문서·안내문의 일관된 격식체 `~습니다`는 올바른 한국어 목소리다. 구어체로 바꾸지 않는다.
- 글쓴이 고유의 말투, 유머, 방언, 특정 시기의 표현.
- 기술 용어와 고유명사. 정확한 용어는 슬롭이 아니다.
- 이미 구체적이고 사람다운 글은 손대지 않는다.

레지스터별 처리는 영어와 같다. 블로그·에세이는 목소리를 살리고, 기술·법률·공지 문서는 중립적이고 평이한 격식체가 곧 사람의 목소리다.

## 표준 용어 조회

용어 선택이 미심쩍을 때(특히 영어에서 옮긴 전문 용어) 국립국어원 오픈 API로 표준 용어·정의·대역어를 확인한다. 클라이언트와 명세는 `references/korean-terminology.md`.

```bash
node <skill-dir>/bin/korterm.js search "머신러닝"   # 표준 용어·대역어·정의
node <skill-dir>/bin/korterm.js define "용어"        # 품사·뜻풀이·용례
```

조회 결과는 근거이지 자동 치환이 아니다. 문맥에 맞는지 판단하고, API에 없다고 틀린 용어로 보지 않으며(신조어·사내 용어), 글쓴이가 의도한 표기는 보존 규칙을 따른다. 인증키(`KLI_API_KEY`)가 없으면 이 조회는 건너뛰고 나머지 검수는 그대로 진행한다.
